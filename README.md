# NB League 매거진 2026-27 — 데이터 파이프라인

Yahoo 판타지 농구 리그(ID 80126)의 데이터를 매일 수집해, 기사 작성에 쓰는
**주간 팩트시트**를 만드는 저장소입니다. 기사는 팩트시트에 있는 숫자만 씁니다.

```
Yahoo API ──매일──> data/2026/raw (원본 XML, 그대로 보관)
                         │ 재구성 (언제든 다시 가능)
                         v
                    league.db (SQLite, 저장소에는 올리지 않음)
                         │
                         v
                    data/2026/facts/week-NN.md · .json  ──> 기사 작성 · 검증
```

## 원칙

- **원본 우선.** API 응답을 가공 없이 저장합니다. 파서에 문제가 있어도 다시
  수집할 필요 없이 `sheets`만 다시 돌리면 됩니다.
- **선발 슬롯 기록만 합산.** 날짜별 로스터를 저장하므로, 벤치·IL에 있던 날이나
  다른 팀 소속이던 날의 기록은 섞이지 않습니다.
- **공식 숫자와 대조.** 선수 기록 합계가 Yahoo 공식 팀 합계와 다르면 팩트시트
  맨 위 "데이터 점검"에 표시됩니다. 표시가 있으면 그 숫자는 기사에 쓰지 않습니다.
- **순위는 직접 계산.** 카테고리 승-패-무 누적, 무승부는 0.5승. Yahoo 순위와
  다르면 역시 점검 항목으로 표시됩니다.

## 처음 한 번 설정 (API 경로, 승인 후)

1. PC에서 `python3 scripts/yahoo_auth.py` 실행 → 리프레시 토큰 발급
2. 저장소 **Settings → Secrets and variables → Actions** 에 세 값 등록
   - `YAHOO_CLIENT_ID`, `YAHOO_CLIENT_SECRET`, `YAHOO_REFRESH_TOKEN`
3. **Actions → collect → Run workflow** 에서 명령을 `smoke`로 골라 실행
   - 로그에 리그 이름, 16개 팀, 카테고리 10개가 나오면 연결 성공
   - 응답 표본이 `data/2026/raw/samples/`에 저장됩니다

## 명령

| 명령 | 하는 일 | 언제 |
|---|---|---|
| `smoke` | 연결 확인, 응답 표본 저장 | 처음 설정 후 |
| `discover` | 내 Yahoo NBA 리그를 시즌별로 나열 | 작년 리그 키를 찾을 때 |
| `draft` | 드래프트 결과 + 평균 픽 + 직전 시즌 기록 저장, 드래프트 팩트시트 작성 | 드래프트 직후 1회 |
| `collect` | 끝난 날짜 수집 → 팩트시트 갱신 | 매일 자동 |
| `sheets` | 수집된 데이터로 팩트시트만 다시 작성 (`--week N`) | 필요할 때 |

Actions 화면의 **Run workflow**에서 고르거나, 로컬에서 `python -m nbl <명령>`.

## 매일 자동 실행

`.github/workflows/collect.yml`이 미국 태평양 시간 00:05에 `collect`를 실행합니다
(한국 시간 16:05, 미국 서머타임이 끝나는 11월 1일 이후에는 17:05).

- **수집 대상**: 방금 끝난 날(D)의 로스터와 선수 기록. 이 시각에는 D의 경기가
  모두 끝났고 D의 로스터는 더 바뀌지 않습니다.
- **누락 보충**: 실패한 날이 있으면 다음 실행에서 자동으로 채웁니다(1회 최대 14일).
- **기록 정정 반영**: 새 주의 첫날을 수집할 때 지난주 전체를 다시 받습니다.
- **실패 알림**: 실행이 실패하면 GitHub가 메일로 알립니다.

## 데이터 위치

```
data/2026/raw/league/     설정, 팀, 주차 일정, 드래프트
data/2026/raw/weeks/      주차별 스코어보드(최신)
data/2026/raw/days/날짜/   그날의 로스터·선수 기록, 순위·트랜잭션 스냅샷
data/2026/facts/          week-NN.md/.json, draft.md/.json, preseason.json
```

## 팩트시트 읽는 법

- 모든 항목에 번호가 있습니다: 매치업 `M`, 순위 `S`, 팀 `T`, MVP 후보 `P`,
  LVP 후보 `L`, 트랜잭션 `X`, 스토리 훅 `H`, 다음 주 대진 `N`, 드래프트 픽 `D`.
- 선수 "점수"는 10개 카테고리의 표준점수 합입니다(턴오버는 감점, 야투·자유투는
  시도 수를 반영). 후보를 고르는 기준일 뿐, 기사에 쓰는 숫자가 아닙니다.
- 트랜잭션 시각은 한국 시간, 주차 경계는 미국 태평양 시간입니다.

## 블로그

`posts/2026/*.md`가 글이고, `python -m nbl blog`가 정적 사이트(`site/`)를 만든다.
main에 올리면 `pages` 워크플로가 GitHub Pages로 발행한다. 글 쓰는 법은
`docs/publishing.md`, 무엇을 언제 쓰는지는 `docs/editorial.md`. 목록은 주차별 상자로
쌓인다. 상자마다 시작/결과/만평 세 칸과, 그 주에 나온 점검·특집·웨이버·호외 목록. 개막 전 글은 Week 0.
목록 위에 검색창이 있다(발행된 글 전체를 `search.json`으로 만들어 브라우저에서 찾는다. 서버 없음).
목록 위의 팀 이름을 누르면 그 팀이 나온 글만 모은 페이지로 간다(팩트시트의 팀 이름을 본문에서 자동으로 찾는다).

## 수집 경로: API와 브라우저

같은 팩트시트를 두 경로 중 하나로 만든다. `config/league.json`의 `source`로 고른다.

| | `source: "api"` | `source: "web"` (현재) |
|---|---|---|
| 실행 | GitHub Actions, 무인 | Claude 세션 + 로그인된 Chrome |
| 원본 | `data/<시즌>/raw/` (XML) | `data/<시즌>/web/` (체크섬 붙은 텍스트) |
| 절차 | `python -m nbl collect` | `docs/browser-collection.md` |

브라우저 경로에서 추가되는 명령: `plan`(무엇을 수집할지), `verify`(저장한 파일 검증).

브라우저 경로는 하루 두 번 읽는다. 밤(한국 22:59)에 경기 전 라인업을, 다음 날 오후에
최종 로스터와 기록을 읽어, 그 사이에 선발/벤치가 바뀐 선수를 팩트시트의
"경기 전 라인업 변경"(번호 `C`)에 싣는다.

## 현재 상태 (2026-10-12)

- **Yahoo API는 막혀 있다.** 2026년 7월부터 심사를 통과하지 않은 앱은 403을 받는다
  (토큰 갱신까지는 성공, 호출이 거절됨). 신청: https://sports.yahoo.com/developer/access/
  승인되면 `source`를 `api`로 바꾸고 `smoke`로 응답 표본부터 확인한다. API 파서는
  실제 응답으로 검증된 적이 없다.
- **브라우저 경로는 실제 데이터로 검증했다.** 작년 리그(48698) 3주차의 두 매치업
  (4팀, 7일)을 수집해 `data/2025/`에 넣었다. 선발 슬롯 기록의 합이 Yahoo 공식 주간
  합계와 10개 카테고리 모두 일치했고, 스코어(5-5 두 건)도 일치했다:
  `python -m nbl --config config/league-2025.json sheets`
- 아직 실제로 해보지 않은 것: 16팀 전체 하루 수집의 저장(209줄), 올해 리그 페이지
  (시즌 전이라 기록이 없음), 플레이오프 주, 트레이드가 있는 주, 예약 실행,
  경기 전(당일) 팀 페이지 읽기 — 지난 날짜 페이지와 같은 표라고 가정했다.
- 팩트시트에 아직 없는 것: 다음 주 팀별 NBA 경기 수, 리그 밖 뉴스(부상·이적),
  드래프트의 평균 픽(ADP)과 직전 시즌 기록(브라우저 경로에서는 미수집).
- 개막 전 영입이 시즌 한도에 포함되는지는 Yahoo 화면과 대조해 확인이 필요하다
  (지금은 포함해서 센다).
